# Modular office layout

The office uses six-seat studios in a fixed 640px-wide column. Each studio adds 448px of height, with two columns and three rows of workspaces, a clear central circulation lane, and a shared collaboration / lounge strip. One studio serves 1–6 agents; two serve 7–12. Empty seats are negative space, not placeholder desks. The scene is centered when space permits and scrolls inside a keyboard-focusable floor viewport on narrow screens; native ghosts remain 32 CSS pixels across.

`layout.ts` owns module dimensions, seat coordinates, furniture bounds and activity anchors. New arrivals are sorted by immutable ID and assigned the lowest available slot; names, specialist roles and API ordering do not determine location. Polling retains existing occupants. Absent IDs retain their seat reservation for this page session, so transient partial polls cannot move returning agents. Permanent departures can leave gaps until reload. A fresh load deterministically allocates the current roster; it does not persist previous session assignments or write configuration.

The environment uses smooth canvas paths at device pixel ratio. The renderer caches its static surface until geometry or pixel ratio changes. It continues using the native avatar image cache and the existing floating, facing, reduced-motion, activity and document-handoff controllers. Activity artwork remains local to a layout anchor. Delivery routes use the central lane and stop 48px beside the recipient. Handoff text occupies a dedicated row above the scroll viewport so wrapped titles remain visible and never cover desk labels. Pipeline, providers and read-only server boundaries are unchanged.
